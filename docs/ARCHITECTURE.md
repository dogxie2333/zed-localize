# 架构决策

## 用户运行版

默认 Cargo features 不含 AI。嵌入已校验的社区目录和人工批准的目标清单，使用 mmap + goblin + Aho-Corasick 规划，Windows 官方 API 在本工具拥有的暂停进程中应用数据补丁，然后退出。

采用直接进程数据读写，是因为当前后端不需要执行翻译函数或拦截绘制。没有新增 DLL 加载器、远程线程注入器、更新守护进程或长期内存服务。保护检查和事务回滚是本产品所需的胶水。

任何目标哈希变化都先回到英文；源码文本和 AI 草稿更新不会自动改变批准清单。

## 更新维护版

有意保留社区 Python 工具。它已经实现 Rust 字面量提取、控件识别、设置和多行语境分组、术语和受保护内容校验。将它们重写成 Rust 会引入另一套语义和长期维护成本，且不改善编辑器运行性能。

Rust 维护命令使用 async-openai SDK 和 redb；没有自写 HTTP AI SDK 或 JSON 文件数据库。通用提示固定，变动数据置后；局部内容缓存以语义为键，不依赖批次和版本序号。

缓存只在维护阶段加载，模型只处理社区未覆盖且缓存未命中的文案。输出需要通过社区校验器，`null` 留待审。校验器指纹及提示策略改变会使缓存失效。

自动化读公开官方源码，维护草稿与 PR，不修改已安装的应用、不合并 PR、不推广新的运行时哈希。服务端提示缓存属于供应商能力，项目只提供稳定前缀、可选路由键及统计。

## 后续范围

扩大汉化覆盖之前，优先调查官方扩展接口和社区 `apply-universal`/`localization` 的可复用入口。不能通过增加 AI 译文来假装解决短常量内联、布局或 ABI 变化。继续明确候选、内存、排版、视觉与升级的证据边界。
